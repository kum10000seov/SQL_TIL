## 01.

```
개념 이름: SQL
개념 설명: SQL은 Structured Query Language의 약자로서, 데이터베이스와 대화하기 위한 표준 도구로서 단순히 저장하는 수준을 넘어 필요한 정보를 정확하게 추출하고 구조화하는 역할을 담당한다.
활용 상황: SQL은 관계형 데이터베이스에 저장된 대규모 데이터를 안전하게 관리하고, 필요한 정보를 빠르고 정확하게 추출해야 하는 모든 상황에서 핵심적으로 활용된다. 예를 들어, 음식점 배달 앱에서 상품 구매 내역(유저, 음식점, 배달음식, 배치 라이더 등) 등 서비스 구동에 필수적인 데이터를 실시간으로 저장, 수정, 조회할 때 활용된다.
```

## 02.

```
개념 이름: BigQuery
개념 설명: 셀 수 없이 많은 데이터 바다를 상대로 구체적인 특정 답을 얻기 위해 질의(Query)를 던져 답을 건져 올리기 위해 존재하는 구글의 완전 관리형 서버리스 클라우드 데이터 웨어하우스이다. 거대한 데이터 산더미를 다룰 때, 서버 구축이나 인프라 관리 등 물리적 한계를 제거하고 오직 데이터에 어떤 질문을 던질 지(Querying)에 대해서만 온전히 집중하여 비즈니스적 통찰을 얻을 수 있다.
활용 상황: 어플 사용자 행동 로그 분석, 수년 치의 유저 거래 내역 조회 등
```

## 03.

```
개념 이름: Database, Table, Row, Column
개념 설명: Database → Table → Row, Column
활용 상황: 음식 배달 서비스의 데이터 = Row, 유저, 음식점, 배달음식, 배치라이더 등(개별 항목이 Column, 항목에 대한 구체적 정보가 하나의 Row이자 Data가 된다.)
```

# 3️⃣ 확인 문제

## 🧩 문제 1

포켓몬 게임이나 이커머스 산업과 같이 다양한 산업에서는 각기 다른 데이터가 존재합니다. 다음 중 하나의 산업을 선택하고, 해당 산업에서 수집하고 활용될 수 있는 데이터 항목, 즉 컬럼 5가지를 자유롭게 상상하여 나열해주세요.

예시 산업:
- 온라인 음식 배달
- 스마트 헬스 케어
- 중고 거래 앱
- 교육 플랫폼

풀이 과정:

```
- 선택한 산업: 온라인 음식 배달
- 떠올린 컬럼 5가지: 주문번호, 사용자ID, 주문금액, 배달소요시간, 음식점카테고리
- 해당 컬럼이 필요하다고 생각한 이유:
1) 주문번호 : 개별 거래를 고유하게 식별하기 위함
2) 사용자 ID : 고객의 주문율, 선호 식품류 및 식당, 거주지역 등을 분석하여 맞춤형 할인 서비스나 신장개업 식당 추천 등 개별화된 마케팅 전략을 수행하기 위함
3) 주문 금액 : 매출 규모 파악 및 프로모션 효과 등을 측정하기 위함
4) 배달소요시간 : 주문 접수부터 최종 배달 완료까지의 실제 소요 시간을 특정하여 예상소요시간 측정 정확성 개선에 기여하고, 배달 라이거 배치 프로세스의 효율성을 개선하기 위함
5) 음식점 카테고리 : 한식, 양식, 일식, 중식, 카페 등 업종별 트렌드 파악 및 시간대별 주문 분포를 파악하여 마케팅 전략에 반영하기 위함
```

## 🧩 문제 2

이번 강의를 통해 SQL이 왜 필요하다고 느끼는지, SQL을 통해 본인이 어떤 것을 해내고 싶은지를 자유롭게 작성해주세요.

풀이 과정:

```
- SQL이 필요하다고 느낀 이유: 마이크로소프트 엑셀 등 기존의 일반 스프레드시트는 수백만 건에 달하는 대규모 데이터를 다룰 때 행 제한에 걸리거나 물리적으로 엄청난 저장 공간을 요하게 된다. SQL은 거대한 규모의 관계형 데이터베이스에서 필요한 데이터만 정확하고 빠르게 추출하고 가공할 수 있게 해주는 강력한 도구이므로 반드시 필요하다.
- SQL로 해보고 싶은 일: 금융권의 방대한 거시경제 및 재무 데이터를 SQL로 직접 추출하고 결합해보고 싶다.
- 앞으로 SQL을 공부할 때 기대되는 점: 엑셀의 용량 한계나 처리 속도 제약에서 벗어나 수백만 건의 대규모 데이터를 자유롭게 다루는 데이터 핸들링 역량을 갖춰 복잡한 분야에서 남들이 보지 못하는 유의미한 인사이트를 직접 발굴해내는 실무형 분석가로 성장하기를 기대한다.
```
